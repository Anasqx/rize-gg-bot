# Rize.gg — لقّط تيمك

بوت ديسكورد بواجهة سعودية/خليجية، كامل بالأزرار والقوائم. ما يحتاج اللاعب يكتب أي أمر. يدعم روكيت ليق، فالورانت، الشطرنج، وفورتنايت. الشعار المرفق مستخدم بلونه الأصلي `#99F9EA`.

## Deploy from GitHub — Bot-Hosting.net

1. Choose **Import from GitHub** and paste this repository URL.
2. Choose **Node.js 24** (24.17 or newer), with entry file **`index.js`**.
3. Set the startup command to **`npm ci --omit=dev && npm start`**. Dependencies install automatically; you do not need console commands.
4. In the host’s **Environment Variables** settings, add `DISCORD_TOKEN`, `GUILD_ID`, `PANEL_CHANNEL_ID`, and `MATCH_CHANNEL_ID`. Use your own private values. Leave `ENABLE_PRESENCE=false` unless you enable that intent in Discord.
5. Enable **Server Members Intent** in the Discord Developer Portal, invite the bot with the permissions below, then press **Start**.

Player data is saved in `./data/rize.sqlite`; preserve this folder when updating. Run one instance. The free hosting plan currently requires manual renewal every four days. See [host setup](https://bot-hosting.net/docs/guides/set-up-a-server) and [free plan](https://bot-hosting.net/). Host deployment has not yet been tested with a real token.

## تشغيل سريع

تحتاج Node.js **24.17 أو أحدث**، توكن البوت، آيدي السيرفر، وآيدي قناتين نصيتين. توكن البوت ينحط في إعداد خاص عندك، وليس في الشات أو ملف تنشره.

1. افتح تطبيق البوت من [Discord Developer Portal](https://discord.com/developers/applications). سمّه **Rize.gg** وارفع `rize-icon.png` كصورة للبوت.
2. في صفحة **Bot** فعّل **Server Members Intent**. اترك **Message Content Intent** مقفلاً؛ البوت ما يحتاج يقرأ كلام الأعضاء. **Presence Intent** اختياري، مو مطلوب للعدّ الأساسي.
3. من رابط تثبيت التطبيق اختر تثبيت البوت في السيرفر بصلاحيات: **View Channels، Send Messages، Embed Links، Attach Files، Read Message History**. ما يحتاج Administrator أو Mention Everyone أو Manage Messages. إذا تستخدم OAuth2 URL Generator، اختر نطاق `bot`؛ ما فيه أوامر تحتاج تسجّلها.
4. أنشئ قناتين نصيتين عاديتين، مثلاً `🎮・لقّط-تيمك` للوحة و`💬・شات-اللعب` للطلبات والتنسيق. اسمح للأعضاء بمشاهدة القناتين، وبالكتابة في الشات. خَلّ الكتابة في قناة اللوحة للبوت والمشرفين فقط. تأكد أن صلاحيات القنوات ما تمنع البوت من الصلاحيات المذكورة.
5. فعّل **Developer Mode** في إعدادات ديسكورد، ثم انسخ آيدي السيرفر والقناتين من قائمة الضغط باليمين → **Copy ID**.
6. انسخ `.env.example` إلى `.env` واملأ القيم الأربع الأولى. أو أدخل نفس الأسماء في **Secrets / Environment Variables** عند المستضيف. لا تترك القيم التجريبية.
7. داخل مجلد المشروع شغّل:

```sh
npm ci --omit=dev
npm start
```

البوت ينشر اللوحة تلقائياً عند أول تشغيل. يحتفظ بآيدي الرسالة ويعدّل نفس اللوحة بعد إعادة التشغيل. ما يحتاج حتى المشرف أمر سلاش. كل القوائم الشخصية خاصة باللاعب، والطلبات تظهر في شات اللعب.

## الواجهة المبسّطة

اللوحة تعرض «ألعب الحين»، «أبي لاعبين»، «حالتي»، وزر الألعاب مع العدد.
اختيار اللعبة والرتبة يسجّلك جاهزاً فوراً لساعتين. خيار «بلعب بعدين» يظهر بعد التسجيل لمن يحتاجه.
«حالتي» تجمع الجاهزية وروابط الفرق والطلبات. الخطوات التفصيلية أدناه تشمل الأزرار القديمة التي تبقى متوافقة.

نظام المستويات والعجلة ما زال مقترحاً، وليس مفعّلاً.

## طريقة اللعب

- **الألعاب:** يعرض عدد اللاعبين المختلفين الجاهزين الآن. داخل القائمة يظهر عدد الجاهزين لكل لعبة؛ اللاعب يقدر يسجّل لأكثر من لعبة، لذلك مجموع الألعاب قد يتجاوز الرقم الرئيسي.
- **سجّل جاهزيتك:** اللعبة ← الرتبة ← الحين / بعد نص ساعة / بعد ساعة / بعد ساعتين. الجاهزية تستمر ساعتين من البداية. اسم اللاعب هو حسابه في ديسكورد؛ ما يحتاج يدخله يدوياً.
- **ابحث عن لاعبين:** اللعبة ← الرتبة أو أي رتبة ← العدد الناقص ← مراجعة وتأكيد النشر. الطلب يستمر ٣٠ دقيقة. صاحب الطلب محسوب خارج العدد المختار.
- **المنشن:** حتى ١٠ لاعبين مسجلين وجاهزين ومطابقين للرتبة، مع مهلة ١٠ دقائق بين منشنات نفس اللاعب لنفس اللعبة. ما فيه منشن جماعي للسيرفر. الأونلاين لوحده ما يسجّل أحد تلقائياً.
- **انضمام:** يتطلب جاهزية فعّالة لنفس اللعبة ورتبة مطابقة، إلا في طلب «أي رتبة». ينشال تسجيل اللاعب لتلك اللعبة بعد الانضمام، ويتحدّث الطلب بأسماء الفريق. صاحب الطلب ينشال تسجيله لنفس اللعبة بعد نشر الطلب.
- **اعتذار:** يحفظ الاعتذار عن الطلب، ولا يلغي جاهزية اللاعب للطلبات الأخرى. يقدر يرجع وينضم إذا غيّر رأيه.
- **جاهزيتي:** تجديد ساعتين من الآن، أو من البداية إذا التسجيل مستقبلي، أو إلغاء لعبة، أو إعادة التسجيل لتعديل الرتبة والوقت. ضغط التجديد أكثر من مرة ما يراكم ساعات إضافية.
- **طلباتي:** روابط الطلبات اللي أنشأتها أو انضمّيت لها. زر الانسحاب في الطلب يرجّع المقعد متاحاً؛ ما يعيد جاهزيتك تلقائياً. صاحب الطلب أو مشرف عنده Manage Messages يقدر يقفل الطلب.
- كل صاحب طلب عنده طلب مفتوح واحد في نفس الوقت، مع خمس دقائق بين الطلبات. اكتفاء الفريق يقفل الانضمام، ويقدر أحد ينسحب قبل انتهاء وقت الطلب.

## الاستضافة

البوت اتصال مستمر مع Discord، وليس موقعاً. يحتاج عملية شغالة باستمرار، **نسخة واحدة فقط**، ومساحة بيانات دائمة. ما يحتاج دومين أو منفذ ويب أو خدمة ping.

### خيار بدون رسوم استضافة

تشغيله على جهازك بالأوامر السابقة ممكن، لكن يوقف إذا طفيت الجهاز أو دخل في السكون أو انقطع الاتصال. التشغيل المجاني على الإنترنت ما تم اختياره أو إعداده بعد؛ أي عرض مجاني لازم يسمح ببوت يعمل باستمرار، ويوفر Node 24 ومساحة بيانات دائمة. لا تعتمد على عرض مؤقت أو خدمة تنام على أنه تشغيل دائم.

### بخصوص Replit

ممكن تستخدم بيئة التطوير للتجربة إذا كانت تدعم نسخة Node المطلوبة. ضع التوكن في **Secrets**، وثبّت الحزم وشغّل `npm start`.

وفق [وثائق Replit الحالية](https://docs.replit.com/features/publishing/deployment-types)، **Reserved VM** هو النوع المناسب للبوتات المتصلة دائماً وله تكلفة شهرية. Autoscale قد يتوقف عند الخمول، وStatic ما يشغّل البوت. لذلك ما نعتبره حلاً مجانياً دائماً لهذا المشروع.

هذا الإصدار يحفظ SQLite محلياً. لا تنشره على نظام ملفات مؤقت إذا تبي تحتفظ بالتسجيلات والطلبات. قبل استخدام استضافة ما توفر قرصاً دائماً، يلزم نقل طبقة التخزين إلى قاعدة بيانات خارجية؛ هذا التعديل غير موجود في النسخة الحالية.

### Docker على مستضيف بقرص دائم

بعد تعبئة `.env`:

```sh
docker compose up -d --build
docker compose logs -f
```

ملف Compose يحفظ البيانات في volume اسمه `rize-data` ويعيد تشغيل البوت إذا توقف. لا تستخدم `docker compose down -v` إلا إذا تقصد حذف البيانات. لا تشغّل نسختين من البوت أو تشارك قاعدة البيانات بين سيرفرين.

## الإعدادات والبيانات

| الاسم | المطلوب |
| --- | --- |
| `DISCORD_TOKEN` | توكن البوت من Developer Portal، سري |
| `GUILD_ID` | آيدي سيرفر واحد |
| `PANEL_CHANNEL_ID` | آيدي قناة اللوحة |
| `MATCH_CHANNEL_ID` | آيدي قناة الطلبات والشات |
| `PANEL_MESSAGE_ID` | اختياري، رسالة لوحة قديمة مرسلة من نفس البوت |
| `DATABASE_PATH` | الافتراضي `./data/rize.sqlite`، لازم يبقى محفوظاً |
| `ENABLE_PRESENCE` | الافتراضي `false`. إذا `true` فعّل Presence Intent أيضاً |

العداد الأساسي يعتمد على الجاهزية المسجلة. خيار Presence يضيف عدد المسجلين الظاهرين أونلاين فقط؛ الحالة المخفية تُعامل كغير ظاهرة، وما تمنع الانضمام أو المنشن. يستخدم البوت Guilds وGuildMembers intents، والأخير يحذف جاهزية من يطلع من السيرفر ويحدث فريقه. جميع تحديثات العدّ تبدأ من الحالة المحفوظة؛ اللوحة تتحدث كل ٣٠ ثانية تقريباً.

SQLite يحفظ آيديات الأعضاء، اللعبة، الرتبة، الأوقات، الطلبات، المنضمين، والاعتذارات. لا يحفظ نصوص الشات. الجاهزية المنتهية تنحذف تلقائياً، وسجل الطلبات ينحذف من قاعدة البيانات بعد يوم من انتهاء الطلب. رسائل الطلبات القديمة في ديسكورد تبقى؛ يقدر المشرف يحذفها. نسخ احتياطية آمنة: أوقف البوت مؤقتاً وانسخ مجلد `data` كاملاً، ثم شغّله.

الرتب تصنيفات عامة للتنسيق: بدون تقسيمات I/II/III، والشطرنج فئات تقييم يختارها اللاعب بنفسه. ما فيه تحقق من حساب اللعبة أو قواعد أهلية الرانكد، ولا فلترة منطقة أو منصة أو طور في هذا الإصدار. الروكيت يدعم طلب حتى لاعبين إضافيين، فالورانت أربعة، فورتنايت ثلاثة، والشطرنج خصماً واحداً.

## التحقق قبل استقبال الأعضاء

شغّل البوت في سيرفر تجريبي بحسابين حقيقيين:

1. تأكد أن اللوحة ظهرت بالشعار والأزرار.
2. سجّل الحساب الأول «الحين»، وافتح طلباً من الحساب الثاني لنفس اللعبة والرتبة. تأكد من المنشن.
3. انضم وتأكد أن اسم الحساب ظهر وأن المقعد تقفّل عند الاكتمال.
4. جرّب الانسحاب، تغيير الجاهزية، وإقفال الطلب.
5. أعد تشغيل البوت وتأكد أن نفس اللوحة والأزرار تشتغل.

الاختبارات المحلية تغطي التوقيت، المطابقة، مهلة المنشن، منع الزيادة على المقاعد، إعادة التشغيل، صلاحيات إقفال الطلب، وفشل النشر. تشغيلها:

```sh
npm test
```

تم اجتياز ٩ اختبارات محلية. **لم يُختبر الاتصال الحي بديسكورد، ولم يُنشر البوت على استضافة**؛ التوكن والآيديات غير مضافة. يلزم اختبار السيرفر أعلاه للتأكد من صلاحيات حسابك وظهور الرسائل فعلياً.

## للمطوّر

`games.js` للألعاب والرتب، `ui.js` للنصوص والأزرار، `handler.js` لتدفق التفاعل، `store.js` للتخزين والمطابقة، و`index.js` للاتصال والتحديث. ملفات الأزرار ثابتة وتعتمد على حالة محفوظة، وليست مؤقتة بمدة جلسة البوت.

شعار PNG جاهز ومرفق. لإعادة إخراجه من SVG الأصلي بعد تغييره:

```sh
npm ci
npm run brand
```

مراجع التنفيذ: [Discord components](https://docs.discord.com/developers/platform/components)، [Gateway intents](https://docs.discord.com/developers/events/gateway)، [discord.js](https://discord.js.org/).
